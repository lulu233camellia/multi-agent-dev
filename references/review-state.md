# 审核状态模板

有独立审核或返工循环时使用。将下面必要字段合并到已有验收报告；没有既有记录时，可用单个 `review-state.md`。协调者维护总状态，其他角色返回结果，避免并发覆盖。

## 当前状态

```text
工作项：
目标与验收约定位置：
基线：本次变更的固定比较起点
当前候选：HEAD + 未提交 / 未跟踪相关文件的内容摘要，或可复现的内容指纹
指纹范围与计算方式：包含哪些源码、配置、测试、依赖锁文件及必要非代码资源
审核轮：已启动轮数 / 已批准上限
当前轮范围：完整首轮 / 指定增量与影响面
状态：WORKING / CHANGES_REQUIRED / PASS / BLOCKED / NEEDS_DECISION
首要结果：尚未就绪 / 可用入口及限制
```

仅用 `HEAD` 不能代表有脏工作树的候选。不要把密钥、真实用户素材正文或大文件全文写入状态；必要时只记录受控路径及摘要。没有 Git 时用本次相关文件的内容摘要标识版本。

审核轮在发起前记录；恢复时读取记录，不从零开始。服务调用失败的重试单独记尝试次数，不包装成成功审核，也不增加授权预算。

## 有效证据

| 检查 | 命令或操作 | 结果 | 内容标识与覆盖范围 | 相关环境 / 输入 | 当前仍有效？ |
| --- | --- | --- | --- | --- | --- |
| 填实际检查 | 填实际命令或观察方法 | passed / failed / not_run | 实际覆盖的模块或行为 | 对结果有影响的版本、配置、样本 | 是 / 否及理由 |

复用前判断相关输入是否变化。无关文案变动通常不使后端单测失效；依赖更新或共享配置变动可能使多个检查失效。真实媒体、浏览器、集成与单测证据分开标记；Fake 或结构检查不能证明真实服务和用户体验。

由项目要求、验收约定或具体风险决定必需证据。缺少必需证据时标记 `BLOCKED`，不能把未执行填成通过。项目要求独立执行的检查不以开发自测替代。

## 问题表

| ID | 根因 / 对象 / 失败方式 | 首见轮 | 位置与触发证据 | 阻断性 | 状态 | 处理理由与核验证据 |
| --- | --- | --- | --- | --- | --- | --- |
| F001 | 实际问题身份 | 实际轮次 | 文件、符号、触发输入和后果 | blocking_current_outcome / follow_up | open / resolved / rejected / deferred | 事实理由或证据位置 |

问题位置变化时保留 ID。同根因的多个实例可以列在同一行或子列表中；修复跨出授权范围时先标明影响并取得缺失决定，不无限扩展修改。

新报告漏提旧问题不等于解决。逐项检查未关闭阻断项；有效修复才能标记 `resolved`。记录为 `deferred` 的事项不能仍让必需验收条件失败；严重问题的风险接受不能由 Agent 自行代替有权人决定。

## 每轮记录

```text
轮次 / 时间 / 候选：
本轮接收的旧问题：
审核范围与专项角色：
发现：新增 / 复用旧 ID / 有新证据重新打开
核实后处理：修复 / 拒绝 / 延后
新增证据及失效证据：
结论与下一步理由：
服务调用失败 / 重试次数（如有）：
```

若要继续，下一步必须能说明改变了什么、还欠什么证据；“再检查一遍”不是理由。记录要短，不保存整段模型对话。

## 结论

- `PASS`：本轮约定的验收条件满足、必需证据有效、没有未解决阻断项。仍可附非阻断后续项；不代表已部署。
- `CHANGES_REQUIRED`：有已核实、范围内可修复的阻断问题，且审核预算允许继续。
- `BLOCKED`：缺少必需环境、权限或验证条件，无法完成要求的判断。
- `NEEDS_DECISION`：需要范围 / 方案 / 风险裁决，或已达到审核停止条件。交付当前候选和明确选项，不继续自动循环。

首要结果就绪与最终关闭分别记录。可展示的预览不自动等于验收通过；任何尚缺的生产或人工验证都要明示。
