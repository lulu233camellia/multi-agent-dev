# Multi-Agent Dev · 多 Agent 全流程应用开发

用多 Agent 协作，把应用从需求和方案推进到实现、验收、交付与持续迭代。

这是一个以中文编写的 Agent Skill，适用于从零构建应用，也适用于接手已有项目、开发新功能和维护迭代。它组织整个开发过程中的目标、分工、上下文和交接，让每个阶段都服务于可用的应用成果。快速变更和审核收敛是其中控制协作成本的机制。

## 覆盖的开发流程

| 阶段 | 推进内容 | 可交接的结果 |
| --- | --- | --- |
| 需求与范围 | 明确目标用户、使用场景、核心流程和本轮边界 | MVP 或迭代范围、可观察的验收条件 |
| 产品与技术方案 | 确定交互、数据与接口边界，处理关键依赖和技术不确定性 | 足够支持实现的方案与关键决定 |
| 任务拆分与协作 | 按可运行的功能安排实现顺序，明确角色和写入范围 | 有依赖关系与负责人的开发任务 |
| 开发与集成 | 实现功能，接通相关模块，验证实际行为 | 可运行的应用或功能增量、检查证据 |
| 验收与修复 | 对照用户流程验收，必要时安排独立验证，处理阻断问题 | 验收结论、已修复问题与剩余项 |
| 交付与迭代 | 提供运行或预览入口，按授权完成发布，接续用户反馈 | 可使用的成果、明确的环境状态与下一步 |

从项目当前阶段接续；已有需求、方案和有效证据直接复用。全流程覆盖不要求每个小任务都重新走一遍所有阶段，也不要求每个阶段都生成独立文档。

## 协作解决什么问题

- 应用开发停在需求或方案，后续实现与交付没有持续推进。
- 规划、开发与验收之间缺少明确边界，需求或接口在交接时走样。
- 多个 Agent 同时修改共享文件，或切换聊天后丢失当前任务和结论。
- 已经完成的小改动因重复审核和重复测试迟迟不能交付。

## 工作方式

协调者维护目标、方案、依赖和交付进度；开发者完成实现与集成；验收者独立判断结果。需要解决具体技术不确定性时，再增加实验角色。

| 场景 | 执行方式 |
| --- | --- |
| 小范围文案、样式和普通缺陷 | 单 Agent 最小修改与相关检查 |
| 跨模块功能或需要独立验收的任务 | 协调者锁定范围，开发者实现，独立验收者检查 |
| 有具体重大风险的变更 | 增加必要专项检查，并保留项目要求的人工门槛 |

角色按任务需要启用，不要求每次建立固定人数的团队。“快速变更”由当前开发 Agent 执行，不要求另设常驻 Agent。

### 审核如何结束

首轮查看本次完整变更。修复后的复核默认围绕未解决问题、修复差异与受影响行为；扩大范围需要具体理由。有效测试证据可以复用，项目必需的独立检查与 CI 仍须完成。

问题使用稳定 ID 跟踪。已有结论需要新证据才重新打开，范围外建议不会自动变成本轮任务。默认审核上限为三轮，满足条件可提前结束；到限仍有阻断问题时，报告当前状态和下一步。用户明确要求额外复核，可以追加对应预算，历史轮数继续累计。

这些规则受当前用户指令和项目约定约束。Skill 是行为指导，不是能在运行时强制拦截调用的限流器。

## 安装

使用 Skills CLI：

```bash
npx skills add lulu233camellia/multi-agent-dev --skill multi-agent-dev -g -a codex
```

也可以将完整仓库克隆到自己的 Skill 目录。以下示例仅适用于目标目录尚不存在时：

```bash
git clone https://github.com/lulu233camellia/multi-agent-dev.git ~/.codex/skills/multi-agent-dev
```

其他 Agent Skills 兼容工具可以使用其自己的 Skill 目录。实际代理分工能力取决于宿主提供的工具；没有独立代理能力时，不能声称已完成独立验收。安装后若未被发现，重新打开会话或重载宿主。

## 使用示例

```text
使用 $multi-agent-dev 从零开发一个预约管理应用，推进需求、方案、实现和验收，交付可在本地运行的 MVP。
```

```text
使用 $multi-agent-dev 接手这个已有应用，沿用当前架构，完成本轮功能开发、集成、验收和交付。
```

```text
使用 $multi-agent-dev 推进应用的下一版，复用当前需求和验证结果；其中小范围 UI 修改由当前开发 Agent 直接处理。
```

已有长期团队时复用当前登记和任务文件。创建新的长期聊天须由用户明确要求；单次任务分工使用宿主可用的子代理能力。普通问答、寻找 Skill 和内容创作团队不属于本 Skill 的范围。

## 验证与限制

初版协作与审核规则完成过六个合成流程场景的一轮独立推演，覆盖小改动、重复问题、预算追加、过期证据、重叠写入和真实验收缺口。推演发现的一处预算授权歧义已修正。本次全流程说明与入口调整通过了 Skill 结构、相对引用和元数据检查。

这些检查尚未验证按本 Skill 从零完成一个应用的实际效果，也不是项目速度或缺陷率基准。应结合真实项目的交付结果、审核轮数、等待时间和遗漏缺陷评估效果。
